# 配置与注意事项

## 一、配置文件说明

### apo/config.yaml —— 轮数、预算、权重、路径

```yaml
max_rounds: 3               # 优化轮数
max_llm_calls: 100          # LLM 调用总预算（生成/打分/优化统一计数）
weights:                    # 评分权重（加权计算与评分员提示词文案共用这一份）
  startup: 0.4              # 能否无报错启动
  requirement_match: 0.3    # 功能匹配需求
  safety: veto              # 标记性字符串，不参与加权，命中即 0 分
  delivery_completeness: 0.3 # 交付完整度
paths:                      # 相对 apo/ 目录的路径（脚本基于自身位置解析）
  best_prompt: "best_prompt.md"
  logs_dir: "logs"
  backups_dir: "backups"
```

### apo/test_tasks.yaml —— 任务集

| 任务 | 类型 | 需求 |
|---|---|---|
| d1 | dev | 批量重命名文件的小工具（前缀 + 序号） |
| d2 | dev | 统计文件夹里各类型文件数量和大小的命令行工具 |
| d3 | dev | 带按钮窗口的简易记事本，能保存/打开 txt |
| h1 | holdout | 按扩展名分类整理文件，执行前先列出将移动的文件并等确认 |

- `dev_tasks`：每轮评估用；`holdout_tasks`：仅最终验收用，防过拟合。
- 加任务会增加预算消耗（每任务约 2 次调用）。

### apo/acceptance_criteria.yaml —— 验收标准清单

包含"能无报错启动 / 核心功能可用 / 有清晰结构和说明 / 无危险操作"四条。
**⚠️ 该文件被加载并传入 `llm_judge`，但函数体内没有使用**——评分提示词是硬编码的。
改这里的评分标准不会影响实际打分。

### apo/best_prompt.md —— 当前最佳提示词（可变状态文件！）

- 既是下一轮优化的输入，又会被脚本覆盖，**不是文档**。
- 误覆盖后只能从 `apo/backups/round_*/best_prompt.md` 恢复。
- 引擎在读取与保存时都会经 `strip_code_fence` 清洗首尾代码围栏，
  即使优化器 LLM 误输出 ``` 围栏，也不会被写进该文件。

## 二、已知陷阱（改代码/配置前务必先读）

1. **best_prompt.md 是可变状态**，见上文。
2. **预算按 LLM 调用次数计，不按轮数**：3 dev + 1 holdout、3 轮约 22 次调用。
3. **配置与代码的对应关系**：
   - `weights` 同时驱动加权计算**和**评分员提示词里的百分比文案，改一处即全局生效；
   - `acceptance_criteria.yaml` 加载了但评分逻辑不用（见上文）；
   - `safety: veto` 只是标记，不参与加权；安全与否决走 `hard_check` / `safety_veto`
     两条路，任一命中直接 0 分。
4. **文件统一为无 BOM 的 UTF-8**，内容全为简体中文。脚本读取 YAML 时用
   `utf-8-sig`，兼容带 BOM 的旧文件；运行时把 stdout / stderr 一并重配为 UTF-8，
   既绕开 Windows 控制台 GBK 报错，也保证异常 traceback 写入日志后仍是合法 UTF-8；
   新建同类文件保持无 BOM UTF-8。
5. **插件路径约定**：`run_apo.py` 只认 `~/apo/apo_loop.py`，引擎挪位置必须同步改脚本。
6. **logs/ 与 backups/ 是运行时产物**，已被 `.gitignore` 忽略，不要提交到仓库。

## 三、目录结构总览

```
crush-apo-project/
├── README.md                       # 项目说明（本仓库入口）
├── requirements.txt                # Python 依赖（openai / pyyaml）
├── .gitignore                      # 忽略运行时产物与环境文件
├── apo-optimizer/                  # ① Crush 插件（Skill）
│   ├── SKILL.md                    #    触发条件 + 执行步骤
│   └── scripts/run_apo.py          #    后台启动器
├── apo/                            # ② APO 引擎工作区
│   ├── apo_loop.py                 #    唯一源码文件，整个闭环
│   ├── config.yaml                 #    轮数/预算/权重/路径
│   ├── test_tasks.yaml             #    dev + holdout 任务集
│   ├── acceptance_criteria.yaml    #    验收标准（当前未被实际使用）
│   ├── best_prompt.md              #    当前最佳提示词（会被覆盖）
│   ├── logs/                       #    每轮日志 round_N_*.log / crush_bg_*.log（运行时生成）
│   └── backups/round_N_时间戳/     #    每轮开始前的快照（运行时生成）
└── docs/                           # ③ 本说明文档
```

## 四、想扩展时改哪里

| 目标 | 改法 |
|---|---|
| 换优化目标（优化别的提示词） | 改 `test_tasks.yaml` 任务集 + `best_prompt.md` 初始提示词 |
| 加评测任务 | 编辑 `test_tasks.yaml` 的 `dev_tasks`/`holdout_tasks`（注意预算） |
| 调评分权重 | 只改 `config.yaml` 的 `weights`（加权与评分文案共用这一份） |
| 调停止条件 | `config.yaml` 的 `max_rounds` / `max_llm_calls` |
| 换模型 | 改 `apo_loop.py` 顶部的 base_url / MODEL_NAME |
