# 使用手册 · 小公司 Agent 指挥中心 v1.1.1

一个 Windows 桌面"小公司"：你当老板，三位数字员工（claude / opencode / crush）在一个受管控的工作区里接活干活，所有命令、文件写入、花费都在你的审批与预算之内。v1.1：提示词可外置自定义、调度更聪明、界面换 macOS 风、新增终端模式（`agentcompany` 命令直接对话 CEO）。

---

## ① 这是什么

一句话：**把"一句话需求 → 拆解 → 执行 → 评审 → 交付"整条流水线搬进一个可拷贝的 exe**。

```
┌─────────────────────────── 小公司 · Agent 指挥中心（WPF 壳）───────────────────────────┐
│  组织        任务看板          运行监视           审批中心            预算总览      设置  │
│  (三卡/自检) (DAG预览/确认)   (事件流/直发)      (逐条批/拒)        (三路熔断)   (可移植) │
└───────────────┬──────────────────────────────────────────────────────────────────────┘
                │  A2aGateway（调度中枢：CEO 拆解 → DAG 波次执行 → FIFO 并发闸门 → 熔断）
                │                        CeoPlanner ── 拆 DAG（人工确认后开工）
   ┌────────────┴────────────┬─────────────────────┬──────────────────────┐
   │  claude（CEO 兼首席）    │  opencode（主力执行）│  crush（测试评审）     │ ← 三员工 CLI
   │  规划/架构/分派          │  代码实现/构建       │  只读评审/中文报告     │   (无头子进程)
   └────────────┬────────────┴──────────┬──────────┴──────────┬──────────┘
                │  AgentCliProcessHost（进程宿主：stdin 下任务 / stdout 收事件 / 看门狗 / Job Object 陪葬）
                │                        McpBridge（公司工具 MCP：file_read/write/list + terminal）
                │                        ↕ 命名管道 → 审批门（白名单外命令逐条批准/拒绝）
                ▼
        workspace\（每个任务一个目录：pipeline\task-N ── 产物、review.md、MEMORY.md）
        %APPDATA%\AgentCompany\（state.db 状态库、diag.log、bridge.log、备份）
```

日常用法：**任务看板**提需求 → CEO 拆出节点图（人工确认开工）→ 员工自动执行 → 需要越权命令时**审批中心**等你决定 → 产物落 workspace，评审岗出具 review.md → **预算总览**看花费。全程无需命令行。需求既可以手输一句话，也可以点 **[选择计划]** 读取 .md 计划文件全文（读入后可编辑再提交，UTF-8/GBK 编码自动识别，任务标题取计划首个标题行）。

## ② 员工与角色

| 员工 | 角色 | 模型 | 计量 | 说明 |
|------|------|------|------|------|
| claude | CEO 兼首席 | glm-5.3 | token + 墙钟 | 把一句话需求拆成 1–5 节点 DAG（谁干、依赖谁、只准写哪些文件）；也可在运行监视页直接派活 |
| opencode | 主力执行 | 智谱 Coding Plan | token + 墙钟 | 代码实现、修 Bug、跑构建 |
| crush | 测试评审 | glm-5.3-flash | **token 记 0，只计墙钟** | 纯文本评审员：只读代码与产物，输出中文评审报告（宿主代存 review.md）；被禁止执行命令与写文件 |

- **满编约定**：凡产出代码或交付物的需求，CEO 拆解的最后一个节点一定是 crush 评审节点（depends_on 指向实现节点，write_targets=["review.md"]）。
- **并发**：默认同时最多跑 2 条任务（设置页可调 1–4），超出的排队（卡片显示"排队中"），腾位自动开跑。单任务内 DAG 节点并发也可调（设置页"单任务节点并发上限"，默认 2 = v1.0 行为；**同员工节点自动串行**，跨员工才并行——避免同员工 CLI 自己抢限流）。
- **自检与禁用**：启动自检三个 CLI 是否可达；不可用的员工组织页整卡灰显"未安装"，派活被禁并在设置页给出原因——装好或在设置页填路径覆盖后[重新自检]即恢复。
- **崩溃恢复**：强杀/崩溃后重启，运行中任务标"已中断"，可一键[重跑此步骤]或[整条重跑]。

## ③ 审批与安全

四道闸，全部默认从严（fail-safe = 拒绝）：

1. **命令白名单**：`git status/diff/add/commit`、`npm test`、`npm run build`、`dotnet build/test`、`node -v`、`dir/ls` 直接放行；**其余任何命令**（如 `npm install`）走命名管道请求宿主审批——审批中心逐条显示来源任务、完整命令与 120 秒独立倒计时，超时按拒绝。**没有"全部批准"按钮（安全考虑），只有"全部拒绝"。**
2. **路径沙箱**：所有文件读写被限制在当前任务工作区内；绝对路径指向区外或 `..` 穿越直接拒绝，不进审批。
3. **文件所有权**（DAG 模式）：每个节点只准写自己 `write_targets` 声明的文件，越界写 DENIED——防止两个节点互相覆盖。
4. **员工封锁**：三员工的内置 Bash/写文件类工具一律禁用，只能走公司工具（受 1–3 管控）；crush 更严——`.crushrc` deny 全部执行/写类工具，只留只读（view/ls/grep/read/glob）。

## ④ 预算与熔断

每条任务三路上限（创建时或默认值设定）：

- **token**：按每次 CLI 调用入账（budget_ledger），到上限即熔断终止；crush 记 0。
- **墙钟**：任务累计运行秒数；等审批的时间不计入（不会因你没点按钮被误杀）。
- **重跑**：每任务重跑次数上限，防无限重跑烧钱。

**预算总览页**：并行任务实时预算（一行一条在跑任务 + 合计汇总，各任务独立结算互不串账）、任务 × 员工 token 矩阵（crush 列 token 0 · 墙钟计量）、熔断历史。

## ⑤ 自定义提示词（v1.1 新增）

四处提示词（CEO 规划词 + 三位员工的约束词）都可以**不改代码**直接改：

- **外置目录**：`%APPDATA%\AgentCompany\prompts\`，四个文件——`planner.md`（CEO 拆解规则）、`claude.md`、`opencode.md`、`crush.md`（员工约束）。设置页「提示词」区可查看来源（内置/外置）、编辑、[保存此份]、[恢复默认]，也可[打开提示词文件夹]直接改文件。
- **三态回退（改坏也不停摆）**：外置文件**不存在** → 用内置词；**存在但缺必含锚点**（安全约束句）→ 拒用该文件回退内置（设置页红字提示 + diag.log 留痕）；**合法** → 生效。GUI 与终端模式读**同一份**，改一处两端生效。
- **锚点校验（安全底线）**：planner 必含 `"nodes"`；claude / opencode 必含公司工具与 `file_write` 约束；crush 必含只读约束——防止改提示词时把"只能走公司工具"的安全条款改丢。
- **公司记忆**：`workspace\MEMORY.md` 现在按窗口读尾部（默认 40 行），不再全文塞给 CEO——记忆涨了拆解也不变慢。想全文：设置 `memory_window_lines=0`。

## ⑥ 终端模式 · agentcompany（v1.1 新增）

不想开 GUI，在 PowerShell 里直接对话 CEO：

```powershell
agentcompany                    # 进入 REPL：多行输入需求，空行提交
agentcompany --folder D:\proj   # 预置项目文件夹：宿主代读目录树（深度 3）拼进拆解输入
```

- **REPL 命令**：`/folder <绝对路径>`（设置/切换文件夹并打印树摘要）、`/peek <相对路径>`（读 ≤50KB 文件拼进下次拆解）、`/status`（最近任务）、`/budget`（token 台账）、`/memory [n]`、`/prompts`（四键来源）、`/quit`；Ctrl+C 优雅退出（在途任务标"已中断"，可回 GUI 一键重跑）。
- **流程同 GUI**：提交 → CEO 拆出 DAG 表格（节点/员工/写目标/依赖）→ `y=确认开工 r=重新拆解 n=取消` → 实时事件流 → 白名单外命令弹终端审批（`y/n`，115 秒倒计时，超时=拒绝）→ 终态打印产物清单。审批记录、预算、状态库与 GUI **同库共用**。
- **与桌面版互斥**：同一时刻只能开一个宿主——GUI 开着时 CLI 会提示"桌面版正在运行"退出（反之亦然），关掉一个再开另一个即可。
- **安装**：设置 → 可移植与自检 → [安装终端命令]（写入用户 PATH，**新开**终端生效）；或直接调 `publish\agentcompany.cmd`。
- **中文乱码**：老式 conhost 终端若显示乱码，先执行 `chcp 65001` 再启动（Windows Terminal 默认正常）。

## ⑦ 常见问题 FAQ

**Q1：提示"PATH 上找不到 claude/opencode/crush"（自检未通过）怎么办？**
没装或不在 PATH。两条路任选：① `npm i -g @anthropic-ai/claude-code @opencode/cli @charmland/crush` 后**重开本程序**（PATH 是启动时快照）；② 设置页"可移植与自检"填该 CLI 的完整路径覆盖（.cmd 或 .exe 均可），点[重新自检]。CLI 装在非标准位置（如 nvm 目录切换后）用 ② 最稳。

**Q2：历史上出现过中文乱码 / 进程残留，成因与处理？**
- **中文乱码**：成因是 Windows 命令行默认 GBK 码页——任务文本若走命令行参数就会被弄花。本程序的任务文本一律走 **stdin UTF-8 管道**，系统提示词走 UTF-8 临时文件，已根治；你只需保持"员工配置"环节按《换机部署清单》设置 UTF-8 相关项（claude 的 settings.json 环境变量即可）。若在旧版本日志里看到乱码，属历史记录，不影响新任务。
- **进程残留**：成因是强杀宿主时子进程（node/CLI）未必跟着死。本程序用 **Job Object 陪葬**（宿主死 → 整棵进程树 5 秒内全灭）+ **启动清扫**（下次启动按 PID 记账杀残党、任务标"已中断"、清临时文件，全部记入诊断日志）。你一般无需手动处理；若任务管理器里仍见残留 node 进程，重启本程序一次即可由清扫收尾。

**Q3：如何完全重置？**
三步：① 关闭本程序；② 删除数据文件夹 `%APPDATA%\AgentCompany`（状态库、日志、备份全在这；设置页有[打开数据文件夹]直达）；③ 按需删除工作区（默认在 exe 旁 `workspace\`，或在设置页看你配的根目录）。重开程序即回到全新状态。**只想保数据重置程序**：删除/替换 publish 文件夹即可——状态库不在程序目录里。

**Q4：换一台机器怎么部署？**
照《换机部署清单.md》逐步执行（Node.js → 三个 CLI → 智谱鉴权 → 拷贝 publish → 首次启动自检），每步都附"如何验证成功"。

**Q5：CEO 拆解失败，日志显示"Not logged in · Please run /login"怎么办？**
成因：claude CLI 自动更新到 ≥2.1.314 后，`--restricted`（CEO 拆解用的受限模式，防 CEO 越权）开始**忽略用户级 settings 文件**——`%USERPROFILE%\.claude\settings.json` 里的智谱端点/token/模型映射读不到，claude 误以为没登录。本程序已在 CEO 调用上显式补传 `--settings` 指向你的 settings.json（实测修复），升级本程序即可。若旧版本遇到：任务卡上点 [重新拆解] 前，先升级程序；终端里 `claude -p "只回两个字：收到"` 能通就说明 CLI 本身鉴权正常，问题只在受限模式传参。

**Q6（v1.1）：自定义提示词改坏了会怎样？需要手动恢复吗？**
不需要。外置文件缺必含锚点（如把 claude.md 里的公司工具约束句删了）会被**自动拒用并回退内置词**——公司照常运转，设置页该键显示红字原因（缺哪些锚点），diag.log 同步留痕；点[恢复默认]或补回锚点后[保存此份]即恢复外置。整夹删除 prompts 目录 = 全部回内置。安全底线：锚点校验保证"员工只能走公司工具"这类硬约束不可能被改丢。

**Q7（v1.1）：终端模式和桌面版能同时开吗？多台机器共享一个状态库吗？**
不能同时开：GUI 与 CLI 共用同一条审批管道（单宿主互斥），后开的会直接提示退出——关掉一个再开另一个。状态库在同一台机器上也是共享的（`%APPDATA%\AgentCompany\state.db`）：白天 GUI 跑的任务、晚上终端里 `agentcompany` 提交的需求、审批历史与 token 台账都在一处；跨机器不共享（库不随 publish 走）。
