# 迭代计划 2.0｜手机端中文化 + 可视化远程操作（CMD / 文件资源管理器 / Edge）

> 本计划是《Tailscale手机远程访问Agent执行计划-1.0》的**增量迭代**，不是替代。
> 1.0 的全部架构、文件、服务、验收结论**保持原样，不做任何修改**；本计划只做**纯新增**。
>
> **核心约束（每个迭代都必须遵守）**：
> 1. 不修改 1.0 已交付的任何文件、脚本、服务配置和启动方式（`交付/` 目录内容只读）。
> 2. 不改 Web UI（OpenChamber / cptr）的任何代码、参数、端口。
> 3. 所有新能力通过**新端口 + 新服务 + 新文件**实现，目录统一放在新增的 `交付-v2/` 下。
> 4. **唯一例外——policy file**：Tailscale policy file 全局只有一份，无法"另建新文件"。允许且仅允许**追加**新 grant 规则（追加到 `grants` 数组末尾），1.0 已有的 `tagOwners` 和 `tcp:443` 规则原样保留、一个字符都不动。每次追加前先备份当前文件。
>
> **测试两段式（每个迭代都必须执行）**：
> - **阶段一：本地模拟手机**——在电脑本机用浏览器开发者工具的手机模拟（iPhone UA + 触摸事件）访问 `127.0.0.1` 与 Serve 地址，跑通全部功能才允许进入阶段二。
> - **阶段二：实机测试**——iPhone（Tailscale App 开启）通过 `https://<电脑名>.<tailnet>.ts.net:<端口>` 真机验证。

---

## 一、现状盘点（迭代基线）

1.0 已交付并在运行的资产（全部视为只读基线）：

| 资产 | 位置/端口 | 状态 |
|------|-----------|------|
| Agent Web UI | `127.0.0.1:3000` / `127.0.0.1:8000` | 运行中，不改动 |
| Tailscale Serve | 443 → 本地 UI 端口 | 运行中，不改动 |
| policy file | `交付/policy-file.json` | 只允许追加 grant |
| 启停脚本 | `交付/start-agent-ui.ps1`、`stop-agent-ui.ps1` | 只读，v2 新建自己的脚本 |
| 验收基线 | A1–A5 | v2 不得使其回退 |

**Serve 可用公开端口余量**：443（已被 1.0 占用）、**8443、10000**（空闲，归 v2 使用）。

## 二、目标架构（纯增量）

```
iPhone（Safari，中文界面）
   │ Tailscale (tag:mobile)
   ├── 443  ──→ 1.0 原 Web UI（不动）
   ├── 8443 ──→ [新] 中文门户页 + Web CMD（ttyd）      127.0.0.1:9800
   └── 10000 ─→ [新] 可视化远程桌面（Guacamole→RDP）    127.0.0.1:9900
                                    │
                                    └── 电脑真实 Windows 桌面会话
                                        ├── 文件资源管理器（原生 GUI）
                                        └── Edge 浏览器（原生 GUI）
```

选型理由：
- **CMD 可视化**：`ttyd`（Windows 版）把真实 cmd/PowerShell 渲染成浏览器终端，手机上直接敲命令，体验接近本机。
- **资源管理器 + Edge 可视化**：这两个是 Windows 原生 GUI 程序，"和电脑上没太大差别"的唯一可行路径是**把真实桌面串流到浏览器**。Apache Guacamole（HTML5 客户端 → RDP）零客户端安装，手机 Safari 直接打开即是可操作的完整 Windows 桌面，资源管理器和 Edge 就是真的本机程序。
- **中文门户页**：一个新增的静态导航页（全中文），手机上作为三个能力（原 UI / 命令行 / 远程桌面）的统一入口，不碰原 UI 的任何界面文件。

## 三、迭代拆分

> 三个迭代相互独立、可单独回滚（回滚 = 停新服务 + 删追加的 grant 行，基线毫发无损）。
> 顺序执行：R1 → R2 → R3。

---

### 迭代 R1｜手机端中文门户页

**目标**：手机访问一个新增的中文导航页，可一键跳转到 1.0 的原 Web UI（并为 R2/R3 预留入口位）。

**纯新增内容**：
1. 新建目录 `交付-v2/portal/`，内含 `index.html`（全中文、移动端自适应、大按钮触摸友好）。
2. 新增静态服务：用 `caddy file_server` 或 `npx serve` 绑定 `127.0.0.1:9800`（新端口，不与 3000/8000 冲突）。
3. 新增脚本 `交付-v2/start-portal.ps1` / `stop-portal.ps1`（独立 pid 文件，不动 1.0 脚本）。
4. Serve 追加：`tailscale serve --bg --https=8443 9800`。
5. policy file **追加**（不修改已有行）：
   ```json
   "ip": ["tcp:443"]   // ← 1.0 原规则，保持不动
   // 在其后追加新 grant 对象：
   { "src": ["tag:mobile"], "dst": ["tag:server"], "ip": ["tcp:8443", "tcp:10000"] }
   ```

**R1 测试**：
- 阶段一（本地模拟）：Chrome DevTools → iPhone 14 模拟 → 访问 `http://127.0.0.1:9800`，检查中文渲染、按钮布局、跳转原 UI 正常。
- 阶段二（实机）：iPhone 访问 `https://<电脑名>.<tailnet>.ts.net:8443`，验证同上 + 关闭 Tailscale 后不可达。

**R1 验收**：
| 编号 | 验收项 | 放行标准 |
|------|--------|----------|
| R1-A1 | 中文显示 | 门户页所有文案为中文，无乱码 |
| R1-A2 | 基线无损 | 1.0 的 A1/A3 复测通过，原 UI 行为与 1.0 交付时一致 |
| R1-A3 | 独立回滚 | 停掉 9800 服务并删除追加 grant 后，一切回到 1.0 状态 |

### 迭代 R2｜手机可视化操作 CMD 命令行

**目标**：手机浏览器里打开一个真实的 cmd/PowerShell 终端，直接输入命令并看到输出。

**纯新增内容**：
1. 安装 `ttyd`（Windows amd64 发行版）到 `交付-v2/tools/ttyd/`（新目录）。
2. 启动（仅回环 + 凭据认证）：
   ```powershell
   .\ttyd.exe -p 9801 -i 127.0.0.1 -c <用户名>:<强密码> pwsh.exe
   ```
   - `-c` 基本 auth 是应用层防线；终端进程建议使用 1.0 Step 5 的专用系统用户运行，与 Agent 同级隔离。
3. 门户页**新增一个入口文件段落**（只在 `交付-v2/portal/index.html` 中追加"命令行"卡片——该文件本身是 v2 资产，不算改 1.0）。
4. Serve 端口规划：R2 与 R1 同站暴露，通过门户页跳转 `https://...:8443/ttyd/`（caddy 反代子路径）或直接复用 8443 站点的子路径配置（全部写在 v2 新配置文件中）。

**R2 测试**：
- 阶段一（本地模拟）：手机模拟访问终端页 → 输入 `whoami`、`dir`、`ipconfig`，确认输出实时回显、中文不乱码（PowerShell 设置 `[Console]::OutputEncoding = [Text.Encoding]::UTF8`，写在 v2 的启动脚本里）。
- 阶段二（实机）：iPhone 虚拟键盘输入命令、Safari 弹出基本 auth、会话在手机锁屏后仍存活。

**R2 验收**：
| 编号 | 验收项 | 放行标准 |
|------|--------|----------|
| R2-A1 | 命令执行 | 手机上执行 `ipconfig` 能看到正确输出，交互式命令可正常交互 |
| R2-A2 | 中文输出 | `dir` 中文文件名、`ping` 中文提示无乱码 |
| R2-A3 | 认证 | 无凭据访问终端被拒绝（401） |
| R2-A4 | 基线无损 | 1.0 原 UI 与 R1 门户页复测正常 |

---

### 迭代 R3｜手机可视化操作文件资源管理器 + Edge

**目标**：手机浏览器打开电脑真实 Windows 桌面，直接鼠标/触摸操作资源管理器和 Edge，体验与本机接近。

**纯新增内容**：
1. 新建目录 `交付-v2/guacamole/`，部署 Apache Guacamole（guacd + web app）或轻量替代 `noVNC + RDP-to-VNC` 桥，绑定 `127.0.0.1:9900`。
2. 连接目标：本机 RDP（Windows 专业版启用远程桌面，`localhost` 会话或专用会话）；连接配置写在 v2 新配置文件中。
   - **体验要点**：使用"接管控制台会话"（`admin connect` / shadow session）模式，手机看到的就是电脑当前桌面，资源管理器、Edge 与本机操作**同一画面**，与"和电脑上没太大差别"的要求对齐。
3. Serve 追加：`tailscale serve --bg --https=10000 9900`。
4. 门户页追加"远程桌面"卡片。
5. Guacamole 界面自带中文语言包（客户端语言跟随浏览器 `zh-CN`），无需改其代码。

**R3 测试**：
- 阶段一（本地模拟）：电脑浏览器手机模拟访问 `https://127.0.0.1:9900`（或 Serve 地址:10000）→ 打开桌面 → 用鼠标模拟触摸完成：打开资源管理器并浏览 `交付-v2` 目录、打开 Edge 访问任意网页、拖拽窗口、右键菜单。
- 阶段二（实机）：iPhone Safari 完成上述同样操作，另测：
  - 触摸手势 = 鼠标（单指点按=左键、长按=右键、双指=滚轮）；
  - 分辨率自适应（Guacamole 自动缩放至手机屏幕）；
  - 会话保持：手机锁屏 1 分钟再回来，桌面会话不丢。

**R3 验收**：
| 编号 | 验收项 | 放行标准 |
|------|--------|----------|
| R3-A1 | 资源管理器 | 手机上能打开、浏览、新建/重命名文件（在 `交付-v2` 沙盒目录内演示） |
| R3-A2 | Edge | 手机上能打开 Edge、输入网址、页面正常渲染和滚动 |
| R3-A3 | 画面质量 | 帧率可流畅操作（主观 ≥ 交互可用），无明显色差/撕裂 |
| R3-A4 | 中文界面 | Guacamole 客户端菜单显示中文 |
| R3-A5 | 基线无损 | 1.0 A1–A5 + R1/R2 全部复测通过 |

## 四、统一回滚方案（任一迭代失败时）

1. `tailscale serve status` 记录后，`tailscale serve --off` 关闭对应 https 端口（注意不要关掉 1.0 的 443 通道：用 `tailscale serve status` 确认 443 仍在）。
2. 停 `交付-v2/` 下对应服务的 pid。
3. policy file 恢复为追加前备份（原有规则从未被改，恢复即无损）。
4. 复测 1.0 的 A1 与 A3，确认基线完好。

## 五、安全增补（对齐 1.0 的纵深防御原则）

1. 新增三个服务全部**仅绑定 127.0.0.1**，唯一入口仍是 Serve（TLS）+ grants。
2. grants 追加规则保持最小化：`tag:mobile → tag:server` 的 `tcp:8443, tcp:10000`，deny-by-default 不变。
3. ttyd 与 Guacamole 均启用各自的认证（basic auth / Guacamole 用户体系），密码与 1.0 的 UI 密码不同、独立轮换。
4. RDP 桥接仅监听回环；主机防火墙保持 3389 对 LAN/公网封闭（A5 思路沿用）。
5. 所有新凭据写入 `交付-v2/credentials.md`（新建，不改 1.0 的 `credentials.md`），权限同 1.0 要求。
